# 📝 Changelog

## [1.0.0] - 2025-11-18

### ✨ Интеграция Worker в Backend

**Архитектура изменена:** Worker теперь запускается Backend'ом, а не работает отдельно.

### 🎉 Добавлено

#### Backend (FastAPI)
- ✅ **main.py** - FastAPI приложение с lifecycle management
- ✅ **campaign_manager.py** - Управление worker процессами
  - Запуск/остановка кампаний через subprocess
  - Автовосстановление после перезапуска
  - Подготовка runtime окружения
- ✅ **API Роутеры:**
  - `campaigns.py` - CRUD операции с кампаниями, start/stop, логи, статистика
  - `accounts.py` - Управление Telegram аккаунтами, загрузка сессий
  - `dialogs.py` - История диалогов, обработанные клиенты

#### Инфраструктура
- ✅ **requirements.txt** - Все Python зависимости
- ✅ **start.sh** - Bash скрипт для запуска на Timeweb
- ✅ **.gitignore** - Защита секретов (конфиги, сессии, ключи)
- ✅ **config.example.json** - Пример конфига без секретов

#### Документация
- ✅ **README.md** - Главная документация проекта
- ✅ **DEPLOY_TIMEWEB.md** - Подробная инструкция по деплою
- ✅ **LOCAL_DEVELOPMENT.md** - Уже существовала

### 🔧 Изменено

- 🔄 Worker теперь запускается как subprocess вместо отдельного процесса
- 🔄 Кампании автоматически восстанавливаются после перезапуска
- 🔄 Данные сохраняются между деплоями

### 🔐 Безопасность

- 🛡️ Секреты защищены через .gitignore
- 🛡️ Рекомендация использовать переменные окружения
- 🛡️ Удалены секреты из примеров конфигов

### 📦 Деплой

- 🚀 Готово для деплоя на Timeweb Cloud
- 🚀 Backend + Worker в одном приложении
- 🚀 Автоматическое управление процессами

## Миграция с предыдущей версии

Если вы использовали отдельный worker:

1. ✅ Теперь worker встроен в backend
2. ✅ Не нужно запускать отдельно
3. ✅ Управление через API: `/campaigns/{id}/start` и `/campaigns/{id}/stop`
